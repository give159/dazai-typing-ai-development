# 1 読者限定特典：AI駆動開発（ADD）拡張アセットパック

本リポジトリには、書籍内で解説しているAIエージェント向けの設定ファイル群（`engineering-method` / `spec-docs`）のマスターデータを同梱しています。AIを自律的なチームメンバーとしてワークフローに組み込むための実践的コンテキストです。

## 2 ディレクトリ構造と各ファイルの役割

* **`engineering-method/`** ：アーキテクチャ・品質監査コンテキスト
  * **`SKILL.md`**：AIエージェントに「開発標準・品質ルール」を認知させるためのメイン指示書。
  * **`references/method.md`**：具体的な開発プロセスや設計思想が記述された、AI参照用のサブドキュメント。
  * **`scripts/audit_project.py`**：ディレクトリ構造や依存関係をチェックし、技術負債を検知する検証用Pythonスクリプト。
* **`spec-docs/`** ：仕様駆動開発（Specification-Driven）支援コンテキスト
  * **`SKILL.md`**：AIに「仕様書の定義・整合性チェック」の役割を与えるためのメイン指示書。
  * **`references/doc-format.md`**：仕様書（Markdown）に含めるべき必須項目やフォーマットを定義したルールブック。
  * **`scripts/new_spec.py`**：ルールに準拠した仕様書テンプレートを即座に自動生成（ブートストラップ）するスクリプト。
  * **`scripts/check_spec.py`**：記述された仕様書にロジックの破綻やエッジケースの考慮漏れがないかを事前検証するスクリプト。

## 3 本書における活用方法

* **ハルシネーションと手戻りの防止**：実装前に `spec-docs` で仕様を確定させ、AIの暴走を防ぐADDサイクルを体験します。
* **レビュー負荷の軽減**：実装後に `engineering-method` の指示とスクリプトを組み合わせ、AIにコードのセルフチェック（自動監査）を行わせます。
* **プロダクションへの転用**：本書のチュートリアル（太宰治の写経タイピングゲーム）を通じて、これら2つのアセットの連携手法（プロンプト・オーケストレーション）を学ぶことで、自身の業務リポジトリへそのままデプロイ可能になります。
